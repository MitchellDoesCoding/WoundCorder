WoundCorder codebase and integration review
Reviewed: October 12, 2026

Scope
Reviewed the current working tree, including the existing staged measurement changes and the new workflow changes. Covered launch/consent, patient identity/intake, body-map navigation, camera/photo selection, CNN preprocessing and output contract, local model download/inference, results/education, saving/sharing, AR measurement/frame consistency, branding/resources, and Debug/Release packaging. This is a source/integration review with automated checks, not a clinical validation or an exhaustive device/UI certification.

Release findings / remaining work
1. Physical-device validation remains outstanding. The paired iPad was unavailable. Real LiDAR boundary/volume accuracy, camera interruptions, Qwen3.5 GGUF/MNN generation, peak memory, thermal behavior, and Mail delivery require device acceptance testing. RAM eligibility is not a guarantee of successful generation.
2. The bundled segmentation asset is a placeholder. Automatic outlines use the existing RGB/depth fallback; numerical checks and confidence safeguards do not establish clinical boundary accuracy. Labeled captures and clinical validation remain necessary. CNN smoke tests establish the output contract, not diagnostic accuracy.
3. Public examples are now bundled in all configurations following the owner's explicit confirmation that all supplied images are cleared. See ReferenceData/DistributionApproval.txt. Eighteen selected images retain source attribution and watermarks. They have no app file-browser exposure, but displayed/bundled images cannot be made extraction-proof. Source labels were not independently clinically adjudicated.
4. Full VoiceOver, large text, every body-map location/device size, and formal sixth-grade usability acceptance remain outstanding. App Store metadata is prepared locally, not published.

Current refinement pass
- Migrated patient and measurement indexes from legacy defaults to atomic, protected files. Migration retains a protected original and removes defaults only after verified replacement. Corrupt data blocks writes; explicit reload/recovery preserves the current file. Stale writers cannot silently overwrite newer records. Save failures remain visible and do not dismiss the form or claim success.
- Removed name-based legacy patient matching. Old records remain accessible without silently attaching to a different person with the same name.
- Archived the unused legacy volume calculator and camera prototypes outside the app target; removed the obsolete explicit camera build reference. Compatibility screens route through current consent/intake or saved history.
- Separated ordinary photo capture from AR measurement. Photo capture uses AVCaptureSession without mesh scanning or automatic Photos-library writes. Camera denial still allows photo selection.
- Scoped scanner notifications to each capture instance; hidden/stale screens cannot control another scanner. Interrupted manual/guided/volume scans cancel pending work and cannot appear finalized.
- Rejected missing/low/invalid depth confidence and nonfinite/out-of-range depth. Interpolated holes are not treated as observed geometry.
- Validated mask dimensions/strides, finite probabilities, and explicit logit contracts; rejected ambiguous multiclass outputs. Stabilized semantic probabilities/embeddings against numeric overflow. Required a valid background probability before photo acceptance.
- Corrected image orientation/mirroring and resized directly into the model input without an unnecessary full-resolution allocation.
- Preserved measurement source, quality, preliminary status, and units with saved records, result cards, and analysis sharing. Legacy records clearly state when quality/source were not recorded.
- Added stale-index and corruption guards to photo-check saving/deletion.

Issues corrected during this review
- Connected two exact-source-label reference photos per class from the ZIP; kept provenance/checksums; owner-approved examples now ship in Debug and Release.
- Photo-result Save previously discarded analysis and made zero-valued measurement entries. It now persists photo, predictions, tissue outputs, comments, role, demographics/intake, and optional real measurements in a separate store; saved results reopen and can be shared.
- New patients sharing a name no longer merge automatically. Only an explicit record identifier can merge new intake identities.
- MNN input lacked its image placeholder and used the wrong shape/channel/range. It now uses <img>wound</img> and HWC BGR bytes, as required by MNN's vision preprocessing, with free-memory checking, exception handling, and weight release after inference.

- Image resizing normalizes orientation even when an image is already below the size limit.
- VLM comments must parse as bounded structured data and use only the supplied two CNN candidate labels. Invalid output retains the CNN result. Native cards replace raw HTML/JSON output; camera summary text also avoids raw JSON.
- Non-finite CNN outputs are rejected; background/non-skin photos prompt a retake instead of displaying wound labels.
- Fixed a stale download-verification callback that could interfere with a later download attempt.
- Added a full-window privacy cover for app-switcher snapshots, including presented screens.
- Replaced measurement-derived clinical urgency labels with explicitly nonclinical size-index groups. Size alone cannot establish urgency.
- Corrected optional demographic defaults, field units, validation, consent tap targets, and accessibility hiding of the unconsented main screen.
- Removed unconditional simulator linkage of the device-only MNN framework and dead Markdown/HTML presentation code. Updated obsolete backend documentation.
